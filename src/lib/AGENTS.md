# src/lib rules
- "Share via Apps" and "Send the file" go through src/lib/systemShare.ts: the installed app uses the native share plugin (Android WebView has no navigator.share), browsers use navigator.share only where the frame allows web-share, and any refusal falls back to copying the link, so members never see a dead "share failed" message.
- On Android the Install button first uses Chrome's one-tap web-app install when offered (pickAndroidInstallRoute), because the APK always triggers Android's "unknown apps" block that most visitors cancel; the APK stays as fallback and secondary link, and its guide pictures that block with Settings circled. The APK download goes through the app-download function, which relabels the storage file as an Android package named oracle-lunar.apk, because storage serves it as a generic file. The download streams in-page via downloadApkWithProgress so ApkDownloadProgress can warn it may take minutes and vanish on completion (falling back to the browser's own downloader if the stream fails), then the guided steps open.
- Oracle premium speech joins waiting sentences into runs (mergeQueuedSpeech, ≤500 chars) and starts downloading the next run while the current one plays (PrefetchedSpeech plays arrived bytes then streams the rest); the voice request retries once only on server replies sent before any charge, and the device voice is a last resort that never repeats words already heard, because per-sentence sequential requests caused gaps and mid-reply voice switching.
- Google sign-in in the installed Android/TV app runs in Chrome (Google blocks embedded web views and the app bundle has no /~oauth service): the app opens oraclelunar.com/native-auth#k=<one-time key>, that page signs in and returns the session AES-sealed with that key via app.oraclelunar.ai://auth, so a hijacked link alone is useless; the website flow is unchanged.
- Oracle's free device voice can't take audio filters (browser speech bypasses Web Audio), so realism comes from shapeDeviceSpeech: punctuation-preserving text (cleanTextForDeviceSpeech), one queued utterance per sentence with slightly raised pitch/rate, lifts on ! and ?, and a softer-but-never-low tone for low moods; the old punctuation-stripping cleaner made it flat and sad.
