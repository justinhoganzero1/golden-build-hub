# src rules
- Library deletes remove only the member's own user_media rows (bulk delete filters by user_id) and never remove storage files, because the same file can still back Movie Maker projects, templates or other saved work.
- Phone layouts never scroll sideways: html/body clip horizontal overflow and option/tab rows wrap instead of using overflow-x scrolling; reserve horizontal scrollers for tables and picture carousels.
- Owner-only pages stay out of every user-facing route list (chat tool menu, tiles, headers) unless the signed-in account is admin; the routes themselves keep RequireAuth + RequireAdmin so hiding is never the only gate.
- Signed-out browser visitors to / always land straight on the Play Store-style download page (AppStorePage); the funny ad page still exists at /ad for direct marketing links but is never a default landing, and the installed app opens PublicWelcomePage instead.
- Google sign-ups (no birthday on the form) pass a one-time 18+ birthday step via RequireAuth → /age-required; a database trigger validates the age and blocks members from changing a saved birthday, so the client gate is never the only check.
- Library shares link to the public /watch player on oraclelunar.com (allowlisted own storage/asset sources only) instead of raw file links, and sent files are re-labelled with their real type, because files stored as generic octet-stream arrive blank on phones.
- Every Library item type shares: inline items (apps = raw HTML, text notes, data: documents) are uploaded to the member's own photography-assets/library/shared folder and signed for 7 days via prepareLibraryShare, stories share their public /stories/<slug> page, and the watch page renders doc shares itself (apps in a sandboxed frame, notes as text) because signed storage links serve everything as text/plain.
- Built-in media pointers (*.asset.json) pass through resolveAssetUrl via a Vite load plugin, so the installed Android/TV/iOS app (https|capacitor://localhost) fetches "/__l5e/..." files from oraclelunar.com while the website keeps relative paths; native shells have no hosted asset paths.
- Google TV support is additive: TV mode (OracleLunarTV user-agent marker from MainActivity, TV UAs or ?tv=1) turns remote arrow keys into focus moves with a visible ring; Android's WebView lacks speech recognition, so the native app swaps in a SpeechRecognition-compatible wrapper over the device's free speech service instead of changing Oracle's mic code.
- Free-plan trials need no card: ensureTrialStart in _shared/freeTrial.ts records a free_trial_starts row (7 days from sign-up) on the first trial-card-setup status check-in or trial generation, and claim_free_trial then allows the trial pictures/video; older trial_card_checks rows still count (later end date wins). image-gen/gemini-video answer upgrade_required (reason duplicate/expired/used) and aiAccessEvents raises the plan paywall, never the wallet modal; failed trial generations give the item back.
- Member Gemini key replies (gemini_key_required / gemini_key_problem) are routed by aiAccessEvents to GeminiKeyAlarm and /ai-key-setup; the setup screen renders consent wording from the gemini-key-setup status reply so stored consent text always matches the screen, and Google-side outages never trigger the key alarm.
- One free trial per person: when a trial starts, ensureTrialStart stores one-way hashes of the account's normalized email, device ID (localStorage+cookie+IndexedDB) and IP in service-only trial_identity_marks (kept after account deletion), refreshed by a daily check-in; a new Free account matching another trial account's mark gets a blocked trial row, while installs on any number of devices stay unblocked.
- RequireAuth forces /ai-key-setup for every non-owner account without a checked Gemini key (member_ai_setup.gemini_verified_at), keeping setup, safety and Settings open; a read error never locks members out because the server still refuses AI without a key.
- Oracle sees attached pictures by sending small JPEG frames (up to 4 for animated GIFs) as image parts on that chat turn; only the latest picture rides along in history so follow-up questions work without resending every photo or inflating member AI cost.
- Paying members get a once-a-day low-wallet pop-up (src/lib/lowBalance.ts threshold) linking to /wallet; free and unlimited accounts never see it, and no payment banner sits at the top of the app.
- Website advert pages (SeoLandingPage) render the AppStorePage download listing first with their topic/FAQ below via its extra slot, identical for people and robots (no referrer-based redirects, which search engines treat as sneaky redirects); they are for search visitors only: menus and Oracle shortcuts route through src/lib/toolDestinations.ts to the real tool, and signed-in members opening an advert path are redirected there, so members never land on a "Get the app" page.
- The owner-only Client Pitch Machine (/admin/pitch-machine, pitch_projects + private pitch-assets, admin-only RLS) runs scan → audit → build → pitch as background pitch-machine steps polled by the page; clients only see /demo/<token> on oraclelunar.com through pitch-demo, which serves the deck and a CSP-locked, watermarked offline demo only while the owner's switch is on and within 7 days, and emails are opened in the owner's own mail app, never sent by the app (cold pitches are marketing).
- Oracle creations (pictures, music, sound effects, narrations) are stored as files in the member's own photography-assets/<uid>/library/oracle folder with a permanent storage reference in user_media, signed when opened; Oracle-written documents are HTML pages that open in the isolated Library viewer, and videos still filming are resumed by saved job ID only, so the Library stays light and nothing is paid twice.
- Library pictures/videos saved from the tinyPreview start date get a ~240px JPEG snapshot (video frame ~1.5s in) stored in user_media.thumbnail_url, made after saveToLibrary and backfilled by visible tiles for server-saved items; older items are never reprocessed so the Library doesn't download every old video.
- Full screen is layered: the Android/TV shell hides system bars in MainActivity (swipe-to-reveal transient bars), the installed web app requests manifest display "fullscreen", and phone/tablet browsers enter the Fullscreen API on the next tap via immersiveFullscreen (skipped on desktop, TVs, iframes and native), because browsers only allow full screen after a user gesture.
- Oracle chat access is decided server-side by memberChatAccess (_shared/freeTrial.ts): paid plans always, Free accounts during the 7-day trial window (from sign-up, or a later card-checked trial end) on their own Gemini key, otherwise plan_required, which OraclePage turns into the kind upgrade reply; the client never pre-blocks Free chat, so trial members always reach real AI.
- Owner member deletion goes through admin-delete-user only: requireOwner (protected admin role), never self or admin accounts, the exact email must match, live Stripe plans are cancelled before the account is removed (abort if cancelling fails), personal content (Gemini key, Library rows, memories, agents) is deleted while money records and trial marks are kept, and each deletion is written to auth_audit_log.
- Oracle's free-trial behaviour is split between the oracle-chat prompt (final trial rule appended last) and src/lib/oracleTrial.ts on the screen, which blocks paid-plan creation markers using the X-Oracle-Chat-Access reply header and supplies the no-cost scripted fallback, because the model alone can't be trusted to skip paid tools.
